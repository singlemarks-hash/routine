# 안드로이드 이식 설계서 — iOS 정본 기준 전면 정합

작성 기준: iOS `main @ 790e625` (정본) / 안드로이드 코드 전수 조사 결과.
원칙(CLAUDE.md): 개별 diff를 따라가지 않고 **iOS 현재 상태를 정본으로 전면 대조**한다.

핵심 사실: 최근 51개 커밋은 전부 iOS만 수정했다. 안드로이드의 마지막 반영은
`dbdb534`(시작일 잠금)까지이며, 그 이후의 그룹 점수 원장 개편·알람 강화·심사 대응·
페이월 수정·UI 정합이 모두 미이식 상태다.

### WP0. 정책 상수 정합 (규모 S — 반나절)

**대상**: `models/Models.kt`
**기준(iOS)**: `TimeLock/Models/Models.swift`

1. `emergency` 점수 **-5 → -10** (`ScoreRules`)
2. `NICKNAME_MAX_LENGTH` **8 → 15** (입력란·안내 문구가 상수를 참조하는지 확인, 하드코딩 잔존 검색)
3. `GroupPolicy.SETTLE_GRACE_MINUTES` 신설 = `START_WINDOW_MINUTES + RESUME_WINDOW_MINUTES + 5` (= 25)

### WP1. 그룹 점수 멱등 원장(도장) 이식 (규모 L — 1~2일) ★P0

**대상**: `services/GroupStore.kt`, `services/SessionEngine.kt`, `AppState.kt`
**기준(iOS)**: `GroupStore.swift` applyScore/revokeScore/repairMyScore, `SessionEngine.swift` occurrenceKey

**⚠️ 착수 전 필수 — 발생 키 정본 확정 (결정 D1)**
iOS 출시본 키: `"{예약UUID 대문자}-{epoch 초}"`, 도장 문서 ID = `MD5("groupscore|{키}")`를 UUID 형식 소문자로.
안드로이드 스위퍼 내부 키는 밀리초라 **그대로 넘기면 도장이 어긋나 멱등이 무너진다.**
→ 안드로이드에서 그룹 점수용 키를 만들 때 **반드시 초 단위 + 예약 ID 대문자 정규화**를 거친다.
(안드 내부 인덱스 키는 밀리초 유지 — 로컬 전용이므로 무해. 서버로 가는 도장 키만 정본 형식.)

구현 항목:
1. `applyScore(roomID, points, occurrenceKey, rank)` — Firestore `runTransaction`:
   - `groups/{roomID}/members/{uid}/scored/{markID}` 읽기
   - 없으면: 도장 기록(points, rank, at) + `score` increment
   - 있으면: `rank < oldRank`면 버림 / 같고 points 같으면 버림 / 그 외 차액만 보정 + 도장 갱신
   - rank 상수: noShow=0, normal=1 (완주·이탈실패·긴급종료·일정취소)
2. `reportScore(...)`는 applyScore를 부르는 래퍼로 축소 — **increment 직접 호출 전량 제거** (`grep FieldValue.increment`로 score 대상 0건 확인, memberCount용은 유지)
3. `revokeScore(roomID, occurrenceKey)` — 도장이 있고 rank가 noShow일 때만 기록된 points만큼 감산 + 도장 삭제
4. `repairMyScore(roomID, observed)` — scored 전량 서버 읽기 → 합계 ≠ observed면 compare-and-set으로 교정, 교정값 반환. 멤버 목록 조회(랭킹 진입) 시 서버 응답일 때만 호출, 왕복 추가 없이 방금 읽은 내 score를 observed로 전달
5. 중도 포기: `applyScore(quitKey, -50, rank=normal)` **먼저** → `quit=true` 나중 (끊겨도 벌점 누락 방향으로 실패하지 않게). quitKey = `"groupquit|{roomID}"`
6. 스위퍼·완주·긴급종료·일정취소 등 모든 점수 진입점에 occurrenceKey 전달 배선

**완료 판정**: 코드 내 `update("score", FieldValue.increment` 0건. 두 기기(또는 iOS+안드) 같은 발생 완료 시 점수 1회만 증가 — 실기기 확인 항목에 등재.
**참고**: Firestore 규칙은 이미 양 플랫폼 공용으로 반영 완료(`docs/firestore.rules`의 scored 허용) — 추가 작업 없음.

### WP2. 그룹 조회 신뢰성 + 방 생애주기 (규모 L — 1~2일) ★P0 포함

**대상**: `services/GroupStore.kt`, `ui/GroupScreens.kt`
**기준(iOS)**: `GroupStore.swift`(finishedAt/doomed/seenActive/hideFinishedRoom), `GroupViews.swift`

1. **myRoomIDs**: `get(Source.SERVER)` + `doc.exists` 확인. 못 읽으면 null(모름) → 이번 새로고침 전체 스킵, **아무것도 지우지 않음** (P0)
2. `finishedAt` = 마지막 발생 + duration + 정산유예 25분. `isFinished = now ≥ finishedAt`, `deleteAt = finishedAt + 30일`
3. '종료' 태그 + 방 상세 최종 결과 화면 + "n일 뒤 방이 삭제됩니다" 안내 + `hideFinishedRoom`(결과만 내 목록에서 숨김)
4. `doomed`(참여 마감 후 인원 미달) 판정: **서버 소스 강제** + 이전 상태 승계(오프라인 캐시로 오판 금지). doomed 방: '삭제 예정' 태그, 알람 취소, **점수화 자체 차단**(스위퍼가 이 방 예약 건너뜀)
5. `seenActiveRoomIDs` 마커(SharedPreferences) — 방 문서 소실 시 "시작 전 취소·해체"와 "보존 만료"를 구분해 벌점 회수 여부 결정
6. disband/leaveBeforeStart **서버 가드**: 트랜잭션에서 현재 status 확인 후 실행(이미 시작한 방 해체 차단 등)
7. 방 상세 하단 액션 5분기 iOS와 동일하게: 종료→나가기 / 취소·해체→나가기 / **시작시각 지났는데 판정 전→액션 없음("확인 중")** / 시작 전→방장 해체·참여자 탈퇴 / 진행 중→중도 포기(-50). 처리 중 버튼 비활성("…중")
8. 그룹 탭 개방: 목록 상시 표시, 잠금 패널 제거 → **비구독 안내 카드**("참여 중인 방은 관리 가능, 새 그룹은 멤버십") + 만들기/참여 버튼에서만 페이월. **조회 실패 카드**("방 정보를 불러오지 못했습니다" + 다시 시도) — 그룹 활동은 로컬에 있는데 rooms가 빈 경우

**완료 판정**: 비행기 모드에서 그룹 탭 진입 → 활동 삭제 경로 없음 + 실패 카드 표시. 하루짜리 방 종료 25분 후 '종료' 태그.

### WP3. 기록 수렴 + 파이프라인 순서 (규모 M — 1일)

**완료 판정**: 동기화 전 스윕 호출 경로 0건(grep). 오늘 끝낸 활동이 오늘 일정에 남고 슬롯은 비는 것 실기기 확인.

## 5. 검증 계획

**CI가 잡아주는 것**: Kotlin 컴파일 + Room KSP 쿼리 검증뿐. 테스트 코드 없음.
→ **로직 오류는 CI로 잡히지 않는다.** iOS 이식 때와 동일하게 WP당 커밋을 잘게 쪼개고, 아래 실기기 체크리스트가 최종 관문.

**실기기 필수 체크리스트** (WP8에서 실행)
1. [P0] iOS 기기 + 안드 기기, 같은 계정, 같은 그룹 활동 완주 → 랭킹 점수 **1회만** 증가
2. [P0] 비행기 모드로 안드 그룹 탭 진입 → 방 목록 유지 또는 실패 카드, **활동 소실 없음**
3. 중도 포기 연타/이중 기기 → -50 한 번만
4. 무음+방해금지에서 알람 → 소리·진동·풀스크린 모두 동작, -10분 예고 수신
5. 하루짜리 그룹 방: 종료 25분 후 '종료' 태그, 다음날 0시 일정에서 제거, 슬롯 즉시 반환
6. 거치가이드: 카운트다운 진행 → 촬영 시작 후 00:00 지나도 계속 촬영, 미시작 방치 시 노쇼
7. 주간일정: 완주 초록/긴급종료 빨강/안전종료 무표시, 지나간 행 흐림
8. 페이월: 네트워크 차단 → 실패 카드+재시도 / 복원 무결과 → 안내 다이얼로그
9. 시작일=종료일 하루 예약 저장, 1개월 밖 시작일 차단
10. 재부팅 후 알람 유지(BootReceiver)

**롤백 안전장치**: 각 WP는 독립 커밋 묶음이므로 문제 시 WP 단위 revert 가능. WP1(도장)은 서버 스키마 추가만 있고 기존 필드를 파괴하지 않으므로 구버전 클라이언트와 공존 가능 — 단 공존 기간엔 구버전이 도장 없이 increment하므로 **안드로이드 공개 배포는 WP1 포함 빌드부터**.

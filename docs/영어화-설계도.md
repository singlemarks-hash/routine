# 앵그리모티 영어화(English Localization) 설계도

> 목표: 시스템 언어가 한국어면 한국어, 그 외 전부 영어로 동작하는 앱.
> 직역이 아닌 영미권 자연어 카피. iOS 정본 → Android 이식 순서 유지.
> 이 문서는 진행 중 매 단계의 완료 기준(게이트)을 함께 정의한다.

## 1. 확정된 설계 결정

### D1. 언어 결정 = 시스템 언어 자동 + 마이페이지 전환 (첫 실행 픽커 없음)
- ko 기기 → 한국어, 그 외 모든 로케일 → 영어.
- iOS: 다국어 지원 시 설정 앱에 '앱별 언어'가 자동 노출 → 마이페이지 '앱 언어'는 설정 딥링크.
- Android: `localeConfig` 등록. 인앱 전환은 **API 33+에서만** `LocaleManager`로 제공,
  12 이하는 시스템 언어 추종. (MainActivity가 ComponentActivity라 AppCompat 전환 없이 가는 최소 리스크 경로.
  12 이하 + 인앱 전환 요구가 실측되면 그때 AppCompatActivity 전환을 별도 과제로.)

### D2. 코드의 기본 언어 = 영어 (한국어가 번역 파일로)
- iOS: 개발 언어를 en으로 전환, 코드 리터럴 영어화, `Localizable.xcstrings`에 ko 번역.
- Android: `values/strings.xml` = 영어(전세계 폴백), `values-ko/` = 한국어.
- 이유: 제3국 로케일(일본·스페인 등)에서 영어 폴백 보장 + 영어 카피가 1급 시민이어야 자연어 품질 유지.

### D3. 저장 데이터는 한국어 정본 유지 + 표시 계층 매핑 (스키마 마이그레이션 없음) ★
검토한 대안: (A) 저장을 키("study")로 전환 — 구버전 앱이 동기화로 받은 키를 화면에 그대로 노출하는
호환성 사고 + 기존 데이터 일괄 마이그레이션 필요. (B) 저장은 지금처럼 한국어 정본, 표시할 때만 로케일 렌더.

**B 채택.** 근거:
- Firestore에 구버전(한글 저장)과 신버전 클라이언트가 무기한 공존해도 안전 — 신버전은 어느 쪽이든 읽고, 쓰는 값도 구버전이 읽을 수 있다.
- DB/Firestore 마이그레이션 제로. 노쇼 결정적 ID 같은 정합성 이슈가 아예 발생하지 않는다.
- 매핑 대상이 유한집합: 태그 7종 + 취소 사유 4종 + note 9패턴. `L10nMap`(가칭) 단일 파일로 양 플랫폼 동일하게 관리.
- 영어 사용자가 프리셋 태그 "Study"를 고르면 내부 저장은 "공부" → ko 기기에서 보면 "공부", en 기기에서 보면 "Study". 양방향 자연스러움.
- note의 보간 패턴("N분 내 미시작")은 정규식 역매핑으로 표시 시 파싱 → "Not started within N min".
- 커스텀 태그·자유입력 사유·닉네임·방 이름은 사용자 원문 그대로 (번역하지 않음).

### D4. 시간·날짜 포맷 = OS 로케일 포맷터로 전면 교체
- iOS `TLFormat.clock/dayTitle`의 `Locale(identifier: "ko_KR")` 고정 제거 → `Locale.current` / `Date.FormatStyle`.
- `durationLabel` "N시간 N분" → en "1h 30m" (홈 배지 `styledHourMinute`의 단위 텍스트 포함).
- 요일 라벨 하드코딩 배열(iOS 5곳+Android) → `Calendar.shortWeekdaySymbols` 계열로 일원화.
- **ko 회귀 기준: 포맷터 교체 후에도 한국어 표시는 바이트 동일해야 한다** (스크린샷 대조로 검증).

## 3. Xcode 1회 작업 패키지 (사장님, 약 15분 — Phase 0 착수 시)

`project.pbxproj` 정책상 Claude가 못 하는 것들을 한 번에 묶는다:
1. **Localizable.xcstrings** 파일 추가 (File > New > String Catalog)
2. **InfoPlist.xcstrings** 추가 — 권한 문구 3종 + CFBundleDisplayName 로컬라이즈
3. 프로젝트 Info > Localizations에 **English 추가**, 개발 언어 확인
4. (권장) **UITest 타깃** 추가 — G2 iOS 스크린샷 자동화용
5. (선택) **Unit Test 타깃** 추가 — G3 iOS 매핑 테스트용

이후 카탈로그 내용 채우기·문자열 추출·테스트 코드는 전부 Claude가 작성한다.

### Phase 1 — iOS 문자열 영어화 (파일 = 커밋 = 게이트 단위)
순서는 의존 역순 + 규모 오름차순. 각 커밋마다 G0 허용 목록에서 해당 파일 제거.

1. Theme/공용 컴포넌트 (버튼·칩·다이얼로그 라벨)
2. Services 88개 — 알람·알림 제목/본문, 채널명 대응 문구 (사용자가 가장 자주 보는 표면)
3. CalendarView(31) → OnboardingFlow(35)+Auth → HomeView(34) → AlarmView(38)
4. SessionView(45) → ReservationEditView(75) → SettingsView(83) → GroupViews(135)
5. Info.plist 3종 + 표시명 → InfoPlist.xcstrings (en 원문/ko 번역)

작성 규칙:
- 보간은 위치 지정자 — 한/영 어순이 다르다 ("N일 뒤 삭제" ↔ "Deleted in N days").
- 단수/복수는 xcstrings plural variation ("1 day" / "2 days").
- 카피는 §6 용어집 준수. 새 용어는 용어집에 먼저 등재 후 사용.

### Phase 2 — iOS 스크린샷 전수 QA
- §5 화면 목록 전체를 en·ko로 캡처, Claude가 전 장 검수. 실패 항목은 레이아웃 수정 커밋 → 재캡처.
- 완료 기준: en 전 화면에 ①한글 잔존 0 ②잘림/겹침 0, ko 전 화면 베이스라인 대비 회귀 0.

### Phase 3 — Android 이식
1. `values/strings.xml`(en)+`values-ko/` 생성, Manifest 라벨 → `@string/app_name`
2. 파일 순서는 iOS와 동일 논리: Common → services(105) → 화면 작은→큰(GroupScreens 145 마지막)
3. `localeConfig.xml` + Manifest 등록, 마이페이지 '앱 언어' 스위처 (33+ LocaleManager / 12↓ 안내 문구)
4. G0 래칫을 kt 파일에도 동일 적용, 단계마다 G2 캡처

### Phase 4 — 표면 마감 + 출시
- 앱 표시명 결정(제안: en "AngryMoti" / ko "앵그리모티") 반영
- iOS 마이페이지 '앱 언어' → 설정 딥링크
- 스토어 리스팅: App Store·Play 영어 설명/키워드/스크린샷 (Phase 2·3 캡처 재활용)
- 주의: 영어 리스팅 심사에서 **영어 약관/개인정보방침 링크를 요구할 가능성 높음** — 최소 영어판 준비를 이 시점 과제로 편입
- G4 실기기 최종 QA → versionCode/버전 상향 → 출시
